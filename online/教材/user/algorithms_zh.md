# 算法



## 包含哪些算法

Spinning Up 软件包实现了以下算法：

- [基础策略梯度](../algorithms/vpg_zh.md)（VPG）
- [信赖域策略优化](../algorithms/trpo_zh.md)（TRPO）
- [近端策略优化](../algorithms/ppo_zh.md)（PPO）
- [深度确定性策略梯度](../algorithms/ddpg_zh.md)（DDPG）
- [双延迟 DDPG](../algorithms/td3_zh.md)（TD3）
- [软演员—评论家](../algorithms/sac_zh.md)（SAC）

这些算法都采用基于 [多层感知机（MLP）](https://en.wikipedia.org/wiki/Multilayer_perceptron) 的 Actor-Critic 结构（非循环网络），因此适用于状态可被完全观测、且观测不以图像为基础的强化学习环境，例如 [Gym MuJoCo](https://gym.openai.com/envs/#mujoco) 环境。

除 TRPO 外，Spinning Up 为每种算法提供两套实现：一套使用 [PyTorch](https://pytorch.org/) 作为神经网络库，另一套使用 [TensorFlow v1](https://www.tensorflow.org/versions/r1.15/api_docs)。（TRPO 目前只有 TensorFlow 实现。）

## 为什么选择这些算法？

我们选择这套软件包中的核心深度强化学习算法，是为了呈现该领域近年发展中一系列有意义的思想演进，并最终聚焦于两种算法：PPO 和 SAC。按照原文撰写时的评价，它们在策略学习算法的可靠性和样本效率方面接近当时的先进水平。这些算法也展示了设计和使用深度强化学习算法时需要作出的若干权衡。

### 同策略算法

基础策略梯度（VPG）是深度强化学习中最基础、最适合入门的算法，因为它的出现实际上远早于深度强化学习本身。VPG 的核心要素可以追溯到 20 世纪 80 年代末和 90 年代初。它开启了一条研究路线，最终发展出更强的算法，例如 TRPO，以及随后不久出现的 PPO。

这一研究路线的重要特点是，所有这些算法都是\*同策略（on-policy）\*算法：它们不使用旧数据，因此样本效率较低。但这是有原因的：这些算法直接优化我们真正关心的目标，也就是策略表现；而从数学上看，计算相应的更新需要同策略数据。因此，这类算法以样本效率换取稳定性。不过，从 VPG 到 TRPO 再到 PPO，可以看到研究者不断发展新技术，以弥补样本效率上的不足。

### 离策略算法

DDPG 与 VPG 一样具有基础性地位，但出现得晚得多。引出 DDPG 的确定性策略梯度理论直到 2014 年才发表。DDPG 与 Q-learning 算法联系紧密：它同时学习一个 Q 函数和一个策略，并通过更新两者来相互促进。

DDPG 和 Q-learning 一类算法属于\*离策略（off-policy）\*算法，因此能够高效地重复使用旧数据。它们利用贝尔曼最优性方程获得这一优势：可以使用\*任何\*环境交互数据训练 Q 函数，使其满足该方程，前提是数据中包含足够多来自环境高奖励区域的经验。

但问题在于，并没有保证说，只要很好地满足贝尔曼方程，就一定能够得到表现优异的策略。\*从经验结果看\*，这类算法确实可能取得出色表现；一旦成功，样本效率也十分可观。然而，缺少理论保证意味着它们可能较为脆弱、不稳定。TD3 和 SAC 是 DDPG 的后继算法，利用多种研究见解来缓解这些问题。

## 代码格式

Spinning Up 的所有算法实现都遵循一个标准模板。每种实现分为两个文件：一个是算法文件，包含算法的核心逻辑；另一个是 core 文件，包含运行算法所需的各种工具函数。

算法文件总是以经验缓冲区对象的类定义开头，用于存储智能体与环境交互的信息。接下来是一个运行算法的函数。PyTorch 和 TensorFlow 版本的算法函数大体遵循同一模板，下面分别说明。最后，每个算法文件还提供一些支持，使算法可以直接从命令行在 Gym 环境中运行。不过，这不是推荐的运行方式；正确方式会在 [运行实验](../user/running_zh.md) 页面介绍。

### 算法函数：PyTorch 版本

PyTorch 实现中的算法函数大致按以下顺序执行任务：

1.  设置日志记录器。
2.  设置随机种子。
3.  实例化环境。
4.  通过作为参数传入算法函数的 `actor_critic` 函数，构建 Actor-Critic PyTorch 模块。
5.  实例化经验缓冲区。
6.  设置可调用的损失函数，同时提供算法特有的诊断信息。
7.  创建 PyTorch 优化器。
8.  通过日志记录器设置模型保存。
9.  设置更新函数，用于执行一轮优化或一步梯度下降。
10. 运行算法主循环：
    1.  让智能体在环境中运行。
    2.  根据算法的主要公式，周期性地更新智能体参数。
    3.  记录关键性能指标并保存智能体。

### 算法函数：TensorFlow 版本

TensorFlow 实现中的算法函数大致按以下顺序执行任务：

1.  设置日志记录器。
2.  设置随机种子。
3.  实例化环境。
4.  为计算图创建占位符。
5.  通过作为参数传入算法函数的 `actor_critic` 函数，构建 Actor-Critic 计算图。
6.  实例化经验缓冲区。
7.  为损失函数及算法特有的诊断信息构建计算图。
8.  创建训练操作。
9.  创建 TensorFlow Session 并初始化参数。
10. 通过日志记录器设置模型保存。
11. 定义运行算法主循环所需的函数（例如核心更新函数、获取动作的函数、测试智能体的函数，具体取决于算法）。
12. 运行算法主循环：
    1.  让智能体在环境中运行。
    2.  根据算法的主要公式，周期性地更新智能体参数。
    3.  记录关键性能指标并保存智能体。

### core 文件

与算法文件相比，core 文件并不严格遵循统一模板，但大致具有以下结构：

1.  **仅限 TensorFlow：** 用于创建和管理占位符的函数。
2.  用于构建特定算法的 `actor_critic` 方法所需计算图部分的函数。
3.  其他实用函数。
4.  与算法兼容的 MLP Actor-Critic 实现，其中策略和值函数均由简单的多层感知机表示。
